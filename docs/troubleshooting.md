# Troubleshooting

## Web and desktop

| Symptom                                                         | Cause                                                                                                                                                      | Fix                                                                                                                                                                 |
| --------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| "Couldn't reach the Hopline server"                             | Server not running, or the wrong URL                                                                                                                       | Check `docker compose ps` or the `npm run dev` output; open `/health` in the browser                                                                                |
| "No room with that code"                                        | Typo, the room expired (30 min), or the creator left                                                                                                       | Create a new room; codes never contain `0`, `O`, `1` or `I`                                                                                                         |
| "That room already has two devices"                             | Someone else joined first, or this device reloaded in a **different tab** (a reload in the same tab rejoins automatically within 2 min)                    | Reopen in the same tab, wait 2 minutes for the old seat to expire, or create a new room                                                                             |
| Stuck on "Connecting", then "Couldn't open a direct connection" | Networks block direct WebRTC (symmetric NAT, mobile data, corporate firewall)                                                                              | Set up a TURN relay (`TURN_URLS` + `TURN_SECRET`, see turn.md); no rebuild needed                                                                                   |
| Phone can't open the QR code / invite link                      | The link points at `localhost`                                                                                                                             | Open Hopline on the computer via its LAN IP (e.g. `http://192.168.1.20:8080`), then share                                                                           |
| "Copy invite link" doesn't copy                                 | Some browsers restrict the clipboard on plain-HTTP LAN addresses (Hopline falls back to an older copy method, which usually works)                         | Copy the code manually, or serve over HTTPS                                                                                                                         |
| Large download fails or the tab crashes                         | Browser memory: received files are held in memory                                                                                                          | Use the desktop app or the CLI for very large files                                                                                                                 |
| "Hide my IP address needs a relay server…"                      | The server has no TURN relay, so the app refused to connect rather than expose your IP                                                                     | Untick the option, or configure a relay (turn.md)                                                                                                                   |
| "Too many requests" when joining                                | 10 wrong codes in a minute from your network                                                                                                               | Wait a minute and check the code                                                                                                                                    |
| Works on localhost but not on your domain                       | Same-site check: the page and `/ws` must be on the same host, or list your site in `ALLOWED_ORIGINS`                                                       | Behind your own proxy, forward the original `Host` header (with port)                                                                                               |
| Transfer slower than the connection should allow                | Long or lossy route with only one connection (badge shows no "N lanes"), or a CPU-bound device: on fast local links the CPU, not the network, is the limit | Wait a few seconds for lanes to open (the badge shows "N lanes"); behind a relay check the coturn `--user-quota` and `TURN_MAX_BPS`; close other heavy tabs or apps |
| Stuck on "Reconnecting"                                         | The other device is offline or asleep                                                                                                                      | It resumes automatically when they return (up to 3 minutes)                                                                                                         |
| Folder dropped but nothing sent                                 | Browsers can't read folders as files                                                                                                                       | Zip it, or use the CLI                                                                                                                                              |

## Desktop app

| Symptom                                                                               | Cause                                                                                                                                                                          | Fix                                                                                                                                                                                                                                                                   |
| ------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Desktop ↔ desktop transfer shows no **Direct link** tag and runs at WebRTC speed      | The other side is a browser, the files were dropped from memory rather than disk, the two computers are on different networks/subnets, or a firewall blocks the TCP connection | Both sides need the desktop app on the same network (or a Tailscale-style `100.64/10` overlay). On Windows, mark the network **Private** and check the `Hopline Direct mode` firewall rule exists (`netsh advfirewall firewall show rule name="Hopline Direct mode"`) |
| Direct link starts, then is slow on Windows or falls back to WebRTC after ~20 s       | Windows Firewall throttles or drops inbound traffic to an app without a rule on networks marked **Public**                                                                     | Settings → Network & internet → your network → **Private**. Reinstall to restore the rule, or allow Hopline on **private** networks when Windows asks                                                                                                                 |
| Windows or macOS asks whether Hopline may accept incoming connections                 | Direct mode listens on a random TCP port for the other desktop app                                                                                                             | Allow it (Windows: **private** networks only). Declining just means files go over WebRTC                                                                                                                                                                              |
| Installed app says "Couldn't reach the Hopline server"                                | The app has no server baked in (built without `HOPLINE_SIGNALING_URL`) and falls back to `ws://localhost:8787/ws`, or it points at the wrong server                            | Create `settings.json` with `{ "signalingUrl": "wss://<your-server>/ws" }` in the app's data folder (`%APPDATA%\Hopline`, `~/Library/Application Support/Hopline`, `~/.config/Hopline`) and restart; see [desktop.md](desktop.md#signaling-server)                    |
| Server refuses the desktop app although the browser works                             | `ALLOWED_ORIGINS` is set, so only the listed origins are accepted                                                                                                              | Add `file://` to `ALLOWED_ORIGINS`                                                                                                                                                                                                                                    |
| "Windows protected your PC" (SmartScreen) when installing                             | The installer isn't code-signed                                                                                                                                                | **More info → Run anyway** (only for files from the project's GitHub Releases page)                                                                                                                                                                                   |
| macOS: "can't be opened because it is from an unidentified developer" or "is damaged" | The app isn't signed or notarized                                                                                                                                              | Right-click the app → **Open** → **Open**, or run `xattr -cr /Applications/Hopline.app`                                                                                                                                                                               |
| Started `Hopline.exe` from a terminal and it "exited" at once                         | The packaged app is a GUI app and detaches from the console                                                                                                                    | It's still running; look for its window or in Task Manager                                                                                                                                                                                                            |

## Docker

| Symptom                     | Fix                                                                       |
| --------------------------- | ------------------------------------------------------------------------- |
| `port is already allocated` | Set `WEB_PORT` / `SERVER_PORT` in `.env`, or stop whatever uses 8080/8787 |
| `web` never starts          | It waits for `server` to be healthy: `docker compose logs server`         |
| UI changes don't appear     | Rebuild: `docker compose up --build -d`                                   |
| `VITE_*` changes ignored    | They're build-time; rebuild the `web` image                               |

## Running without Docker

| Symptom                                | Fix                                                                               |
| -------------------------------------- | --------------------------------------------------------------------------------- |
| `Error: Port 5290 is already in use`   | Another process uses it: set `WEB_DEV_PORT` (and the desktop dev URL accordingly) |
| `EADDRINUSE :8787`                     | Docker's `server` is running: `docker compose down`, or set `PORT`                |
| `Invalid value for X` at server start  | Fix that environment variable; the message says what's expected                   |
| Desktop: "Hopline web build not found" | Run `npm run desktop` (it builds first), or `npm run build`                       |
| Desktop: "Could not download Electron" | Check internet/proxy settings, then run `npm run desktop` again                   |

## CLI

| Symptom                                            | Fix                                                                                                       |
| -------------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| "No sender with code … found on this network"      | Same network? Firewall allowing Node.js (UDP 41899, TCP)? Use `--host <ip:port>` from the sender's output |
| "Nothing is listening at …"                        | The sender exited or the port is wrong                                                                    |
| "didn't accept this code"                          | Typo in the code; codes look like `42-amber-river-falcon`                                                 |
| "Too many failed connection attempts"              | The sender saw 5 wrong attempts and stopped for safety; start a new send                                  |
| "No terminal to ask for confirmation"              | Running non-interactively; add `--yes`                                                                    |
| Windows asks to allow Node.js through the firewall | Allow it on **private** networks so discovery and incoming connections work                               |
